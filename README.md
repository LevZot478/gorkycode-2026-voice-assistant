# GORKYCODE 2026 — Голосовой ассистент задач и встреч

Прототип приложения для управления личными задачами, напоминаниями и встречами через обычные текстовые и голосовые запросы. Проект для отборочного задания GORKYCODE 2026.

> **Статус на 31.10.2026:** интерфейс Streamlit и backend на SQLite добавлены в `main`. AI/LLM и реальное распознавание речи находятся в разработке. Пока отсутствует модуль `ai`, интерфейс использует MOCK-разбор запросов. Публичная ссылка на работающий прототип ещё не добавлена.

## Возможности по техническому заданию

1. Создание задач и напоминаний: «Напомни завтра в 10 позвонить Ивану».
2. Создание встреч: «Добавь встречу с командой завтра в 15:00».
3. Просмотр расписания: «Что у меня на этой неделе?».
4. Поиск старых событий: «Найди задачу про презентацию».

**Важно:** все четыре сценария должны работать с реальным AI-разбором запросов к финальной сдаче. Сейчас часть запросов обрабатывает временная MOCK-функция. Наличие кнопки микрофона не означает, что распознавание речи уже подключено.

## Технологии

- Python 3.10+ — язык разработки.
- Streamlit — веб-интерфейс, чат, запись аудио.
- SQLite — локальная база задач и встреч.
- LLM API и Speech-to-Text — будут подключены модулем `ai`; точный сервис зависит от решения команды.
- GitHub — совместная разработка, ветки, Issues и Pull Requests.

## Архитектура проекта

```text
Текст пользователя ───────────────────────────┐
Аудио → Speech-to-Text (ещё интегрируется) ───┤
                                              ↓
                                       app.py (Streamlit)
                                              ↓
                                  ai.parse_intent (пока MOCK)
                                              ↓
                                   backend.execute_intent
                                              ↓
                               backend.service → database.py
                                              ↓
                                           SQLite
                                              ↓
                                   Ответ в интерфейсе
```

Ключевые файлы:

- `app.py` — интерфейс, чат, запись звука, история, визуализация задач.
- `backend/__init__.py` — публичные функции бэкенда.
- `backend/service.py` — создание, получение и поиск событий.
- `backend/database.py` — соединение SQLite, схема и импорт тестового CSV.
- `backend/models.py` — форматы данных и проверки.
- `tests/test_core.py` — тесты бэкенда.
- `ai/` — ещё не загружен в основную ветку.

### Согласованный интерфейс модулей

```python
from ai import parse_intent, transcribe_audio   # появится после интеграции AI
from backend import execute_intent, list_events

intent = parse_intent(text, now_iso)
result = execute_intent(intent)
```

`parse_intent(text, now_iso)` должен возвращать `dict` с действием `action` и аргументами (`title`, `kind`, `date_time`, `due_date`, `period_start`, `period_end`, `query`, `missing_fields`). `execute_intent(intent)` возвращает `dict` с `ok`, `message`, `event`, `events`, `needs_clarification`, `missing_fields`, `error_code`.

## Локальный запуск

Установите Python 3.10 или новее. Из папки проекта выполните:

```powershell
python -m pip install -U streamlit
python -m streamlit run app.py
```

Обычно веб-приложение открывается по адресу `http://localhost:8501`.

Если проекта ещё нет на компьютере:

```powershell
git clone https://github.com/LevZot478/gorkycode-2026-voice-assistant.git
cd gorkycode-2026-voice-assistant
```

Если проект уже скачан и нет несохранённых изменений:

```powershell
git switch main
git pull origin main
```

**MOCK-режим:** до появления модуля `ai` некоторые запросы обрабатываются упрощённым кодом в `app.py`. Это режим для проверки интерфейса и хранения, а не доказательство реального понимания свободной речи.

## Проверка бэкенда

```powershell
python -m unittest discover -s tests -p "test_core.py" -v
```

В текущем бэкенде предусмотрены тесты создания задач и встреч, поиска, валидации дат, сохранения в SQLite, импорта CSV и обработки ошибок. Успешные тесты backend **не подтверждают** работоспособность полной цепочки с LLM и голосом.

### Проверка сохранения данных через интерфейс

1. Запустите `python -m streamlit run app.py` из корня репозитория.
2. Введите **«Добавь встречу завтра в 15:00»**. Убедитесь, что приложение подтвердило создание записи и показало её в боковой панели.
3. Остановите сервер в терминале через `Ctrl+C`.
4. Запустите той же командой повторно. Проверьте, что встреча всё ещё есть в боковой панели.
5. Для дополнительной проверки можно найти в папке проекта файл `events.db` — SQLite использует его по умолчанию.

Не путайте перезапуск страницы и перезапуск сервера. SQLite должна сохранять записи после обоих.

## Хранение данных

При локальном запуске база по умолчанию — `events.db` в рабочей папке. Путь можно переопределить переменной окружения `DATABASE_PATH`. Этот файл не следует коммитить в публичный репозиторий.

При облачном деплое необходимо постоянное хранилище (внешняя БД либо надёжное постоянное дисковое хранилище). Локальная SQLite на некоторых бесплатных хостингах может пропасть после пересоздания приложения.
