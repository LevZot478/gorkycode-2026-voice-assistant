# GORKYCODE 2026 — голосовой ассистент задач и встреч

Прототип для управления задачами, напоминаниями и встречами на русском языке. Пользователь пишет или записывает голосовое сообщение; AI определяет действие, backend сохраняет и ищет события.

**Исходный код:** https://github.com/LevZot478/gorkycode-2026-voice-assistant  
**Публичный прототип:** ещё не развёрнут; ссылка будет добавлена после настройки хостинга.

## Основные сценарии по ТЗ

1. «Напомни завтра в 10 позвонить Ивану» — создать задачу/напоминание.
2. «Добавь встречу с командой завтра в 15:00» — создать встречу.
3. «Что у меня на этой неделе?» — показать расписание.
4. «Найди задачу про презентацию» — поиск сохранённой записи.

Доступны текстовый и голосовой ввод (распознавание через faster-whisper), уточнение недостающего времени и просмотр ближайших событий. Готовность всех сценариев на публичном сервере требует проверки после деплоя.

## Стек

- **Python + Streamlit** — веб-интерфейс, чат и запись аудио.
- **faster-whisper** — STT, русская речь; `base` по умолчанию, ленивое подключение модели.
- **GigaChat API (Сбер)** — основной облачный LLM. Авторизация через `GIGACHAT_AUTH_KEY` (OAuth, временный Bearer token). Модель `GigaChat-2`.
- **Ollama** — резервный локальный LLM при отсутствии облачного ключа, но **не в production**.
- **Groq** — сохранён как необязательный альтернативный LLM.
- **Supabase** — облачная таблица `events` при наличии URL/ключа.
- **SQLite** — локальные тесты или демо на хостинге с постоянным диском.
- **Docker + Amvera** — готовая конфигурация для российского облака.

```text
Клиент (текст / микрофон)
       │
       ├── аудио → faster-whisper → текст
       ▼
     Streamlit app.py
       ▼
    ai.parse_intent()
       ▼
  GigaChat API / Groq / локальная Ollama
       ▼
   backend.execute_intent()
       ▼
    Supabase / SQLite
       ▼
  Результат в интерфейсе
```

## Локальный запуск

Требуется Python 3.10+ (рекомендуется 3.11).

```bash
git clone https://github.com/LevZot478/gorkycode-2026-voice-assistant.git
cd gorkycode-2026-voice-assistant
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Добавьте **локальный** файл `.env` (он исключён из Git):

```dotenv
GIGACHAT_AUTH_KEY=your_sber_authorization_key
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your_supabase_key
WHISPER_MODEL_SIZE=base
```

Ключ GigaChat получается в <https://developers.sber.ru/docs/ru/gigachat/individuals-quickstart> после регистрации проекта GigaChat API в Sber Studio. Нужен именно **Authorization Key**, а не одноразовый Access Token. Для доступа физлица scope — `GIGACHAT_API_PERS`. При наличии ключа токен получаем автоматически и обновляем в течение работы приложения.

### TLS-сертификат Сбера

Для GigaChat API требуется доверие к сертификату НУЦ Минцифры. При локальной ошибке `CERTIFICATE_VERIFY_FAILED` установите сертификаты по [официальной инструкции Сбера](https://developers.sber.ru/docs/ru/gigachat/certificates) либо задайте `GIGACHAT_CA_BUNDLE=/path/to/verified/ca-bundle.pem`. Проверка TLS **не отключается**. Dockerfile использует официальные адреса скачивания сертификатов и обновляет системное хранилище.

### База данных

При наличии `SUPABASE_URL` + `SUPABASE_KEY` используется Supabase. Используйте отдельную таблицу `events` в формате, который ожидает текущий backend: `id`, `date`, `time`, `text`. Весь контент в публичном прототипе **общий**, авторизация пользователей не предусмотрена. Не храните личные данные.

Если Supabase не задан, применяется SQLite. Переменная `DATABASE_PATH` явно выбирает SQLite, например `DATABASE_PATH=/data/events.db`. **Не задавайте `DATABASE_PATH` одновременно с Supabase**, иначе будет выбран режим SQLite.

## Развёртывание без Streamlit Cloud: Amvera (Россия)

В корне репозитория есть `Dockerfile` и `amvera.yaml`. Для запуска нужно создать приложение в <https://amvera.ru/> и подключить GitHub-репозиторий, затем добавить переменные/секреты в интерфейсе Amvera:

```dotenv
GIGACHAT_AUTH_KEY=...    # Authorization Key из Sber Studio
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2
APP_ENV=production
WHISPER_MODEL_SIZE=base
```

**Хранение — выберите один вариант:**

- Рекомендуется существующая облачная таблица: задайте `SUPABASE_URL` и `SUPABASE_KEY`.
- Для автономного российского облака: `DATABASE_PATH=/data/events.db`. В `amvera.yaml` уже прописан `persistenceMount: /data`, однако постоянство сохранения нужно проверить на своём тарифе.

Порт приложения — `8501`, конфигурация Amvera его пробрасывает. После создания приложения в Amvera подключите публичный HTTPS-домен и проверьте работу в браузере. Сам GitHub не создаёт платный/бесплатный аккаунт хостинга и не предоставляет API-ключи.

Если выбран другой Docker-хостинг, достаточно `Dockerfile`, открытого порта 8501 и этих же переменных окружения.

## Тесты

```bash
python -m pytest -q tests
```

Автотесты проверяют backend и GigaChat-контракт на мокированных HTTP-ответах. Они **не доказывают** доступность реального GigaChat API и не заменяют сквозную проверку.

После деплоя: проверить все 4 сценария, микрофон, сохранение записи после перезапуска и работу HTTPS. Первое голосовое сообщение может обрабатываться дольше из-за загрузки модели Whisper. Нужен небольшой сервер с достаточной оперативной памятью.

## Структура проекта

- `app.py` — Streamlit, чат, запись голоса и список событий;
- `ai/intent.py` — GigaChat OAuth, вызовы LLM и структурирование команд;
- `ai/transcription.py` — локальное распознавание речи;
- `backend/database.py`, `backend/service.py` — БД и операции;
- `tests/` — тесты; `.github/workflows/python-checks.yml` — CI;
- `Dockerfile`, `amvera.yaml` — публикация в российском облаке.

## Безопасность и ограничения

Не отправляйте API-ключи в коммиты, Issues, публичные чаты или скриншоты. Настраивайте их **только как секреты** в панели хостинга. Для публичного демо используйте отдельную тестовую БД без настоящих контактов и личных встреч. Не храните финансовые/личные данные. Приложение пока не разделяет события по пользователям.

**Статус:** код подготовлен для GigaChat API и Docker-развёртывания. Публичный адрес, фактическое соединение с GigaChat и работа без VPN должны быть проверены после настройки учётной записи и секрета.
